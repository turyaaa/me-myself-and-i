# Бібліотека вікторин та акаунти

Сайт уже підготовлений для проєкту `qrnnufayiemqysxfnxps`. `library-config.json` містить URL і **публічний** Publishable key; він призначений для браузера. Secret / service_role ключі сюди не додавати. Права обмежує база, а не приховування публічного ключа.

## 1. Таблиці

У Supabase → SQL Editor → New query встав увесь `supabase-library.sql` і натисни Run. Файл перевірений у PostgreSQL, зокрема повторний запуск. Початкова помилка з CASE виправлена. За успішного виконання з’явиться повідомлення на кшталт «Success. No rows returned».

Для нової версії з профілями після цього виконай **`supabase-accounts.sql`**, а для ролі власника — **`grant-owner-admin.sql`**. Обидва файли перевірені в PostgreSQL і вже виконані власником у поточному проєкті. Після оновлення сайту відкрий профіль — має з’явитися роль «Адміністратор». Іншому акаунту роль надає лише власник через SQL, додавши його справжній `auth.users.id` у `app_admins`; поля публічного профілю не керують правами.

## Email і пароль

Google вже підключений. Форми Register / Sign in додатково підтримують email та пароль. Для email-реєстрації залиш підтвердження адреси ввімкненим у Supabase; листи підтвердження та відновлення повинні повертати на `https://therankinggame.netlify.app/`, як і Google. Посилання відновлення відкривається в тому самому браузері, де його запросили; у профілі з’явиться форма нового пароля. З уже авторизованого профілю також можна задати пароль і надалі входити email/паролем.

**Поштовий сервіс ще не підключено.** Без custom SMTP Supabase надсилає листи лише на адреси учасників команди проєкту; це не підходить для відкритої email-реєстрації гри. Потрібно підключити власного поштового провайдера в Supabase Authentication → Emails / SMTP Settings, вказавши адресу відправника, ім’я The Ranking Game, SMTP host/port/login та пароль провайдера. Секрети вводяться тільки в Supabase, не в HTML/GitHub/чат. Підтвердження email заради обходу поштового налаштування не вимикати.

Оскільки власник поки не має ні SMTP, ні власного домену, цей етап ще попереду. Профіль, адмінські права та Google-вхід від нього не залежать. Реєстрацію через email перевірити на новому власному тестовому email після налаштування доставки; не використовувати чужі адреси для тестів.

Джерела: [Supabase SMTP](https://supabase.com/docs/guides/auth/auth-smtp), [паролі](https://supabase.com/docs/guides/auth/passwords), [профілі користувачів](https://supabase.com/docs/guides/auth/managing-user-data).

## 2. Вхід через Google

У Google потрібен OAuth client; Publishable key Supabase його не замінює.

1. Відкрий [Google Cloud Console](https://console.cloud.google.com/) і вибери або створи проєкт для The Ranking Game.
2. У Google Auth Platform заповни Branding: назва застосунку The Ranking Game, твій email підтримки та контактний email розробника. У Audience вибери External. У тестовому режимі додай свій Google-акаунт до Test users. Для загального запуску потрібно перевести застосунок у Production і виконати вимоги Google, які покаже консоль.
3. У Clients → Create client обери Web application. **Authorized JavaScript origins:** `https://therankinggame.netlify.app`. **Authorized redirect URIs:** `https://qrnnufayiemqysxfnxps.supabase.co/auth/v1/callback`.
4. Google видасть Client ID і Client Secret. **Їх вводиш безпосередньо в Supabase**, не в HTML, GitHub чи чат.
5. Supabase → Authentication → Sign In / Providers → Google: увімкни Google, встав Client ID та Client Secret і збережи. Звір Callback URL з адресою в пункті 3.
6. Supabase → Authentication → URL Configuration: **Site URL** і дозволений **Redirect URL** — `https://therankinggame.netlify.app/`. Не використовуй випадкові адреси інших сайтів. Для окремого тестового розгортання додай його точну адресу окремим рядком.
7. Опублікуй повний пакет на своєму Netlify через GitHub. Бібліотека → Увійти → Продовжити з Google. Перший вхід автоматично створює акаунт автора; пароль гри не потрібен.

Джерело налаштувань: [офіційна інструкція Supabase для Google](https://supabase.com/docs/guides/auth/social-sign-in/auth-google). Google у поточному проєкті вже ввімкнений, а власник успішно ввійшов на сайт. Під час перенесення в інший проєкт ці налаштування потрібно повторити.

## 3. Як користуватися

- Гість бачить опубліковані вікторини, шукає за назвою, відкриває опис і список категорій. Кнопка гри відкриває підготовку локальної гри компанією. Вхід гравцям не потрібен.
- Автор створює вікторину, вказує назву й опис; публічний нік береться з його профілю. Власні старі локальні категорії можна додати кнопкою. На кожну категорію є п’ять питань і відкритих відповідей для ведучого, рівні 100–500.
- Чернетка автоматично зберігається у браузері. «Зберегти приватно» зберігає її в акаунті. «Зберегти й опублікувати» робить її доступною всім. Мінімум для публікації — 5 повних категорій, максимум — 30.
- Якщо редагується опублікована вікторина, приватне збереження **знімає її з публікації**, що явно написано на кнопці. Опублікувати знову можна другою кнопкою. Окремого сховища неопублікованих правок поверх чинної публікації в цій версії немає.
- Для запуску можна вручну вибрати рівно 5 категорій у потрібному порядку або взяти випадкові. Це працює й зі стандартними, власними локальними та змішаними категоріями. Старі неповні локальні набори можна як раніше запускати з меншою кількістю категорій; публікація вимагає повний набір.
- Посилання `?quiz=<id>` відкриває сторінку вікторини. Зняття з публікації закриває це посилання для гостей.
- Автор може видалити свої вікторини; ліміт — 100 збережених вікторин на акаунт. Модерація, скарги, оцінки та статистика популярності поки не додані.

## 4. Перевірки

`npm test` виконує перевірки всієї гри, онлайн-дуелей і PostgreSQL. У `test-library-db.mjs` PGlite виконує справжній SQL із тестовими ролями та mock `auth.uid()` — не імітацію правил дозволу на JavaScript. Перевірені права гостя й двох авторів, приховування приватних даних, заборона чужого редагування/видалення, незмінність власника, конфлікти паралельних правок, валідація публікацій, квота та повторна міграція. Реальний Google OAuth потребує налаштування власником і перевірки після розгортання.

Файли фічі: `library.js`, `library-ui.html`, `library.css`, `quiz-picker.js`, `library-config.json`; вони вбудовані в `index.html`. Для синхронізації після правок — `python sync-library.py`; загальний `sync-features.py` теж викликає цей крок. `build.mjs` читає актуальний публічний конфіг і копіює SDK з `assets`. Жодних секретних ключів для складання не потрібно.

Тексти приватності в грі оновлені відповідно до нових потоків даних; попередні поля власника й контактного email в юридичних шаблонах ще потрібно заповнити своїми даними.
